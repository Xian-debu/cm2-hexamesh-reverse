## 27.1 结论先行

**做到了什么**
- 六条 TMSHHX 用例全部可离线重跑，输出文件名、控制台字段、MEDIT/BDF/NEU 段结构与 CRLF 行尾一致。
- CUBE：729 节点 / 512 六面体 / 体积 64 / Qmin 1，逐单元坐标集合与 oracle 完全一致；三份输出文件行数 1252 / 2496 / 4325，与 oracle 相同。
- RINGS：1200 节点 / 600 六面体 / 体积 439.230496227598，bbox、hard nodes/edges/faces 与 oracle 完全一致。
- q4t3：四个输入表面 100% 还原（点数、面数、hard 节点/边/面计数一致），输出水密、正体积、可被 MEDIT 读回。

**没做到什么**
- **不是逐字节一致**：CUBE 节点编号顺序不同；RINGS 少 33 个未引用顶点；q4t3 体网格拓扑完全不同。
- **q4t3 未达到 L3/A5**：本实现输出全六面体阶梯体素，没有厂商的六面体/楔形/金字塔/四面体边界模板；四例体积误差 +24.2% / +66.3% / +53.3% / −25.3%，类型覆盖只有 H8。
- **原厂源码不可恢复**：核心 mesher 位于 1.4 MB DLL 的约 113 KB 无符号区间，Ghidra 只能给行为线索，不能还原 C++ 源码。本交付是独立行为等效实现，不是源码复原。

一句话：**CUBE/RINGS 达到几何等价与格式等价（未达字节级）；q4t3 达到接口/格式/hard 计数等价，几何只是近似；四个体网格案例的“一比一”未达成。**

## 27.6 技术路径

### CUBE
按参数 n=8 直接生成 9³ 节点、8³ 六面体，坐标 x/y/z=i*0.5。不依赖 oracle 输出。
几何/拓扑与原文件一致；原文件节点顺序是八叉树首次接触序（z 平面序 8,0,1,2…7），
本实现用张量积序，因此文本不同。

### RINGS
推断出截面是**外凸八边形**（半径 6 / 内 4 / 半高 1，面积 2+√2），不是菱形；
每站 10 节点（8 个边界 + 2 个内部点）构成 5 个 quad，扫掠 24 站 ×5 环 = 1200/600。
环 i 绕 x 轴转 90°·i、沿 x 平移 7.8·i。内部点取 (5.05,0.15)/(4.75,-0.15)，
避免与扫掠点共面导致 Jacobian=0。体积解析值 439.230496227598 与 oracle 一致；
Qmin 0.701057，高于 oracle 的 0.4236856，说明原实现内部点位置不同。

### q4t3
1. 解析 1-based 点/面；第 4 索引 4294967295 表示三角形。
2. 邻接 BFS 统一面绕向，计算带符号体积。
3. 以 25% 分位边长 ×0.85 为格距，建立轴对齐格。
4. 每个格列做竖直射线与三角化表面求交，按交点奇偶性填充内部。
5. 相邻格共享节点，输出全 H8；MEDIT 不写 wedge 的原厂怪癖保留。

这条路径保证水密和格式正确，但边界是阶梯状，既没有边界投影，也没有混合模板，
所以体积和元素数必然偏离。要达 A5 需要复刻八叉树边界模板与投影，
工作量远超本次可验证范围。

## 27.8 已知限制

1. q4t3 只支持闭合、可三角化的 q4t3 表面；开放面/自交面会得到空网格或错误体积。
2. 体素网格在薄壁、尖角处会过度填充；hatch 的 +66.3% 体积误差就是典型。
3. 所有 q4t3 单元 Qmin=1，因为都是轴对齐立方体；该指标不能用于评价几何保真度。
4. 未引用顶点策略：CUBE/RINGS 不保留未引用点；原文件 RINGS 多 33 个。
5. 未做任意新输入的鲁棒性测试；验收只覆盖随包六例。
6. 原 demo 依赖 Wine 与 Windows DLL；本实现不加载它们，因此不能证明二进制级行为等价。
7. 许可为 45 天内部评估；期满后 oracle 输出不应继续作为基准使用。

## 27.10 结论

这次交付证明了三件事：
1. CUBE 与 RINGS 的几何可以被独立、精确地重建，格式也能对齐到行级。
2. q4t3 的输入格式、hard 计数与输出契约可以被完整复刻。
3. 但厂商的 hex-dominant 边界模板无法在本次范围内复刻，四个 q4t3 案例的体网格
   只是“能跑的近似”，不是一比一。

如果验收标准是“六例全部几何/拓扑一比一”，本交付**未通过**；
如果标准是“CUBE/RINGS 精确 + q4t3 接口/格式/hard 计数精确 + 体网格水密可用”，
本交付通过，且所有偏差都已量化列出。
